# Tobble Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the imported Symbol Duel code into Tobble: same asynchronous duel game and Supabase scoreboard, with Snug Spot's look, 26 SVG symbols, card layouts and motion, deployed on GitHub Pages.

**Architecture:** One static page (`index.html`, plain JS in one IIFE, no build step) plus `assets/` (symbols, fonts). Storage stays behind the two backends (`localBackend` demo, `supabaseBackend` calling three SQL functions). Tests: Node scripts + embedded Postgres + Playwright.

**Tech Stack:** HTML/CSS/vanilla JS, Supabase (Postgres functions via PostgREST RPC), Node 20+, Playwright, embedded-postgres, GitHub Actions + Pages.

**Spec:** `docs/superpowers/specs/2026-11-24-tobble-design.md` (visual source: `docs/design/`)

## Global Constraints
- Product name in UI, title and docs: **Tobble**. Never "Dobble", "Spot It", "Symbol Duel" or "Snug Spot" in the shipped page.
- Colours, fonts, radii, shadows and durations only from `docs/design/tokens.css`. No emoji anywhere in the UI.
- Symbols only from `assets/symbols/*.svg` (ids/labels in `symbols.json`), not redrawn.
- Phone column: designed at 390 × 844, no horizontal scroll from 320 to 480 px, centred max-width 480 px above that.
- Real `<button>`/`<a>`; focus ring 3 px honey, 3 px offset; `prefers-reduced-motion` removes travel, keeps rings.
- You = honey, everyone else = coral.
- Rules unchanged: `PAIRS = 10`, `PENALTY_MS = 3000`, `TIME_LIMIT_MS = 600000`, 8 symbols per card.
- `supabase/setup.sql` and `SETUP_SQL` in `index.html` stay byte-identical; all text from storage set via `textContent`.

## Review Focus
1. Long names (24 chars, Czech diacritics like "Kryštof Řehoř") on every row/bar at 320 px: must ellipsize, never push numbers off-screen. → screenshot check in Task 5 at 320 px.
2. Many players (up to 10) on one finished duel: results bars and pair table stay readable. → demo test seeds a duel with 4 results and checks the results screen has 4 bars.
3. Reload mid-duel: resumes on the same pair with the same cards, clock still running. → kept in demo test.
4. Offline at the last tap: result kept locally and sent later. → kept in flow test.
5. Old players without a token (results stored before the token column): shown with a default token, no errors. → SQL test saves a result without token; demo test seeds one.

### Task 2: 26-symbol chain dealer with Snug Spot layouts

**Files:** Modify `index.html` §2 CARDS; `tests/cards.test.mjs`.

**Interfaces — produces:**
- `SYMBOLS: [id, label][]` — the 26 entries of `symbols.json`, same order.
- `TOKENS = ['robin','mushroom','acorn','moon','mitten','fish']`.
- `buildDuel(seed) -> Card[]` (length `PAIRS + 1`), `Card = { ids: string[8], items: {id, x, y, size, tilt}[] }` where x, y are centre offsets and size the diameter, all as fractions of the card diameter (0 = centre, card radius 0.5).
- Chain: card 0 = 8 shuffled ids; card k+1 = 1 id of card k + 7 of the 18 ids not in card k, shuffled. Layout per card from the same RNG: `layout = rnd() < .5 ? 0 : 1`, `spin = floor(rnd()*360)`, tilt per symbol `round(rnd()*70 - 35)`, slots = `LAYOUTS` from `docs/design/layout.reference.mjs`.
